# Переезд сайта на российский хостинг

## Зачем

Две причины, и вторая важнее первой.

1. **Сайт не открывается с мобильного интернета.** Проверено 10.09.2026 на реальной
   симке: по Wi-Fi открывается, по мобильному — нет, при этом другие российские сайты
   на той же симке работают. Vercel раздаёт сайт из Франкфурта (`X-Vercel-Id: fra1`),
   и у оператора этот маршрут перекрыт. Аудитория сайта — мастера, которые смотрят
   прайс с телефона между клиентами: для них сайта сейчас нет.
2. **152-ФЗ.** С 1 июля 2025 имя и телефон россиянина не должны впервые записываться
   на сервере за пределами РФ. Сейчас форма отправляет их на функцию Vercel.

Переезд закрывает обе разом.

## Что покупать

Обычный виртуальный хостинг **в SpaceWeb** — там уже зарегистрирован домен `zilma.pro`,
значит DNS менять не придётся, только переключить запись на хостинг. Ориентир 250–350 ₽
в месяц. Требования у нас скромные: PHP 8, 1 ГБ места, `mod_deflate` (есть везде).

Сайт принадлежит Олегу (уточнено 10.09.2026), поэтому решение и оплата — его: ждать
владельца бизнеса, на которого он работает, не нужно. Политика обработки данных и
уведомление в РКН оформляются на того, кому принадлежит сайт.

## Что уже готово в этой папке

| Файл | Что делает |
|---|---|
| `order.php` | принимает заявку, кладёт её в РФ, шлёт на почту и в MAX |
| `orders.php` | просмотр заявок по паролю: имя, телефон, состав, вложение |
| `config.example.php` | настройки — скопировать в `config.php` и заполнить |
| `.htaccess` | **сжатие**, кэш, https и www, 404, защитные заголовки |
| `astro.config.static.mjs` | конфиг сборки без Vercel |
| `../scripts/deploy-to-hosting.py` | выкладка собранного сайта по FTP |

## Порядок переезда (примерно вечер)

1. **Купить хостинг**, получить FTP-доступ.
2. **Разложить файлы:**
   - `public_html/` — содержимое `dist/` после сборки, плюс `.htaccess`, `order.php`, `orders.php`;
   - `zilma-data/` — **рядом с `public_html`, не внутри!** Сюда лягут заявки. Внутри их
     можно было бы открыть прямой ссылкой.
   - `config.php` — тоже вне `public_html`.
3. **Собрать сайт статикой:** заменить `astro.config.mjs` на `deploy/astro.config.static.mjs`,
   удалить `src/pages/api/order.ts`, убрать `<Analytics />` и `<SpeedInsights />` из
   `BaseLayout.astro`, поменять адрес отправки формы в `OrderForm.astro` на `/order.php`.
4. **Выложить** и проверить сайт по техническому адресу хостинга, ДО переключения домена.
5. **Переключить DNS** в панели SpaceWeb. Состояние на 10.09.2026, перед переключением:

   | Запись | Сейчас | Станет |
   |---|---|---|
   | `A` для `zilma.pro` | `216.198.79.1` (Vercel) | `77.222.40.65` |
   | `CNAME` для `www` | `…vercel-dns-017.com` | удалить, вместо неё `A` → `77.222.40.65` |
   | `MX`, `SPF`, проверочные `TXT` | SpaceWeb, Google, Яндекс | **НЕ ТРОГАТЬ** — на них держатся почта и подтверждение прав в поисковиках |

   Разъезжается по интернету от получаса до суток.
6. **Выпустить SSL** (Let's Encrypt, в панели бесплатно) и дождаться https.
7. **Проверить по списку ниже.**
8. **Отключить домен в Vercel** — чтобы проект не пытался его обслуживать.

## Проверка после переезда

- [ ] Сайт открывается **с мобильного интернета без VPN** — ради этого всё и затевалось.
- [ ] `SITE_URL` в `.env.deploy` переставлен с технического адреса на `https://www.zilma.pro`
      и конфиг перевыложен (`scripts/deploy-config.py`) — иначе ссылка в письме с заявкой
      будет вести на технический адрес.
- [ ] Сжатие работает: `curl -sI -H 'Accept-Encoding: gzip' https://www.zilma.pro/ | grep -i content-encoding`
      должно вернуть `gzip`. Если пусто — главная едет как 2,5 МБ вместо 110 КБ.
- [ ] Тестовая заявка доходит письмом на `aiodoggmd@yandex.ru` — с именем, телефоном и составом.
- [ ] Письмо пришло во «Входящие», а не в спам. Если в спам — проверить, что отправитель
      это ящик на домене (`zakaz@zilma.pro`), а не сторонний адрес.
- [ ] По ссылке из уведомления заявка открывается после ввода пароля.
- [ ] Файл заявки НЕ открывается прямой ссылкой из браузера.
- [ ] Каталог, поиск по коду оттенка, палитры в статьях, скачивание прайса, повтор заказа.
- [ ] `https://www.zilma.pro/sitemap-index.xml` отдаётся, адреса страниц не изменились.
- [ ] Старый адрес прайса и адреса статей работают: они уже в индексе Яндекса и Google.

## Куда приходят заявки

Решено 10.09.2026. **Почта Яндекса и MAX** — серверы обоих в России, поэтому туда уходит
заявка целиком: имя, телефон, комментарий. Данные страну не покидают, значит нет и
трансграничной передачи, а с ней отпадает отдельное уведомление в РКН о передаче.

Telegram остаётся необязательным: его серверы за границей, поэтому туда — только состав
заказа и сумма, без имени и телефона. Выключается пустым токеном в `config.php`.

Что для этого нужно завести на хостинге: **почтовый ящик на домене** (например
`zakaz@zilma.pro`) — от него будут уходить письма. Отправлять с чужого адреса нельзя:
почтовые службы считают такое письмо подделкой и кладут в спам.

Уведомление о начале обработки персданных в Роскомнадзор от выбора каналов не зависит —
оно нужно любому, кто собирает контакты, и подаётся один раз.

## Почта: включается ПОСЛЕ ОПЛАТЫ (ответ поддержки 10.09.2026)

Дословно: «Сайт находится в тестовом периоде, поэтому функция sendmail (mail() и
SMTP-соединения) отключена. После оплаты тарифа «Старт» функция sendmail будет включена
автоматически, без дополнительных действий».

Это объясняет всё, что мы намеряли: `mail()` возвращал false при любом отправителе, а
порты 25/465/587 отвечали «Connection refused» мгновенно.

Правильный почтовый сервер — **`smtp.spaceweb.ru`, порт 465, SSL** (не `smtp.sweb.ru`,
как я пробовал сначала). Логин — ящик на домене целиком, например `zakaz@zilma.pro`.

Telegram с этого хостинга недоступен независимо от оплаты — это сетевой маршрут, а не
настройка тарифа. Проверено: таймаут 25 секунд, с обычного компьютера тот же адрес
отвечает за секунду.
