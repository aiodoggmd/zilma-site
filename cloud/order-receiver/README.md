# Приёмник заявок в Yandex Cloud

Заявка с сайта должна впервые записываться на сервере в России — этого требует
ч. 5 ст. 18 152-ФЗ в редакции с 1 июля 2025. Сейчас форма отправляет данные на
функцию Vercel (заграница), и это то самое место нарушения. Здесь — замена.

```
браузер ──POST /order──▶ функция (РФ) ──▶ заявка в Object Storage (РФ)
                              └──────────▶ Telegram: номер, сумма и ссылка,
                                           БЕЗ имени и телефона
```

Раз персональные данные за границу не уходят, трансграничной передачи нет и
уведомлять о ней Роскомнадзор не нужно. Продавец открывает ссылку и читает
заявку целиком — страницу отдаёт та же функция, из России, по паролю.

## Что нужно завести (по одному разу)

1. **Аккаунт Yandex Cloud** — `yandex.cloud`, привязать карту. Списаний не будет:
   бесплатно 1 000 000 вызовов функций и 10 ГБ·час в месяц, у нас это несколько
   заявок в день. Платить придётся только за хранение заявок — это копейки.
2. **Бакет Object Storage**, например `zilma-orders`, доступ — закрытый.
3. **Сервисный аккаунт** с ролью `storage.editor` на этот бакет, для него —
   **статический ключ доступа** (пара «идентификатор + секрет»).
4. **Функцию** с рантаймом `python312`, точка входа `index.handler`, таймаут 30 с,
   память 256 МБ, сервисный аккаунт из пункта 3.
5. **API Gateway** перед функцией — он даёт постоянный адрес и умеет отдавать
   ответы браузеру. Спецификация — в `api-gateway.yaml`.

## Переменные окружения функции

| Переменная | Что это |
|---|---|
| `BUCKET` | имя бакета из п. 2 |
| `S3_KEY_ID`, `S3_SECRET` | статический ключ из п. 3 |
| `TELEGRAM_BOT_TOKEN` | тот же бот `@wella_news_bot` |
| `TELEGRAM_CHAT_ID` | куда слать уведомление о заявке |
| `VIEW_PASSWORD` | пароль на просмотр заявки |
| `PUBLIC_BASE_URL` | адрес API Gateway, из него собирается ссылка в уведомлении |

Секреты хранить в **Lockbox**, а не открытым текстом в настройках функции.

## Почему файл грузится мимо функции

У Cloud Functions потолок тела запроса 3.5 МБ, а фото с телефона легко больше;
плюс base64 раздувает его ещё на треть. Поэтому браузер сначала просит
`POST /upload-url`, получает временную ссылку и кладёт файл **прямо в Object
Storage** — файл тоже остаётся в России, а в заявке хранится только его ключ.

## Что поменяется на сайте

`OrderForm.astro` начнёт отправлять форму на `PUBLIC_ORDER_ENDPOINT` вместо
`/api/order`. Старый маршрут после проверки удаляется — он и есть нарушение,
оставлять его «на всякий случай» нельзя.

## Проверка после развёртывания

1. Отправить тестовую заявку с сайта.
2. Убедиться, что в Telegram пришло уведомление **без имени и телефона**.
3. Открыть ссылку, ввести пароль, увидеть заявку целиком.
4. Проверить, что в бакете лежит `orders/<id>.json`, а вложение — в `attachments/`.
5. Убедиться, что заявка НЕ ушла на `/api/order`: в логах Vercel новых вызовов нет.
