## Прошлый урок (сдан) — Модуль 2, CLs02 «Создание конверсионных сайтов с помощью Claude Code»
`https://university.zerocoder.ru/pl/teach/control/lesson/view?id=347992661`

Учит: структура конверсионного лендинга (hero/польза/доверие/форма-контакты), написание PRD/SPEC в Plan Mode перед генерацией, сборка сайта с нуля через Claude Code, итеративная доработка через скриншоты и текстовые правки, сборка по визуальному референсу, использование Skills, разница локальная/прод-версия.

**Что сдал пользователь (принято куратором):** сайт-визитка про домашнюю маракуйю — тропический фрукт, который он выращивает в России в открытом грунте. Стек: Vanilla HTML+CSS+JS. Структура: hero, польза, доверие, форма и контакты + скилл из урока. Светлый дизайн, цвета взяты с фото упаковки/фрукта. Сам доработал: свой текст в hero (вместо предложенного Claude), анимации (цветочная на графике, летающие плоды, переходы страниц, hover), градиенты между блоками и на рамках карточек, выравнивание под мобильную/десктопную версии. Задеплоено на **Netlify** (бесплатный сабдомен): **https://maracuia.netlify.app/**

**Обратная связь куратора (Антон Хапинский):** дизайн чистый, анимации и адаптивность под разные экраны — хорошо. Замечание на будущее: **повторяющиеся CSS-правила и шрифты стоит выносить/упрощать** — держать в голове при сборке нового сайта, не наступать на те же грабли (дублирование стилей).

## Текущий урок (это ДЗ) — Модуль 4, CLm02 «Деплой проекта: сервер, SSH, SSL и базовая безопасность»
`https://university.zerocoder.ru/pl/teach/control/lesson/view?id=347992725`

Учит: зачем нужен деплой, три типа платформ (managed / хостинг / VPS), термины SSH и SSL/TLS, загрузка статического сайта на хостинг **Beget** через файловый менеджер, покупка домена и настройка DNS, выпуск SSL-сертификата (Let's Encrypt) и перевод на HTTPS, базовые принципы безопасности (что не должно попасть в `public_html`, защита аккаунтов).

**Домашнее задание — выбрать РОВНО ОДИН вариант из трёх:**

1. **Вариант 1 (базовый, бесплатный, ознакомительный).** Реальный деплой не нужен. Подготовить папку проекта (без README/.env/секретов/служебных файлов), `index.html` строго в корне, заархивировать в ZIP, изучить интерфейс Beget (где файловый менеджер, зачем `public_html`), письменно описать шаги реального деплоя (регистрация → создание сайта → загрузка ZIP в `public_html` → распаковка → проверка по техническому домену → домен → SSL), проверить сайт локально в браузере. Отчёт: скрин папки с `index.html`, скрин ZIP, скрин локального запуска, текст с шагами.
2. **Вариант 2 (повторить за экспертом).** Реальный деплой HTML-лендинга/визитки именно на Beget: регистрация → создание сайта → загрузка ZIP в `public_html` через файловый менеджер → распаковка → проверка по техническому домену Beget → (опционально) привязка своего домена + DNS → выпуск бесплатного SSL через Let's Encrypt → проверка HTTPS. Отчёт: ссылка на сайт, скрин файлового менеджера, скрин сайта, скрин HTTPS/SSL, короткий комментарий что получилось/какие сложности.
3. **Вариант 3 (адаптировать под свою задачу).** Взять любой свой проект (с курса или свой) → выбрать подходящую платформу под тип проекта (Beget, Vercel, Railway, Render, Amvera, VPS или другое — не обязательно Beget) → задеплоить → при необходимости домен/DNS/SSL → **спросить Claude Code про идеи развития проекта дальше** (UI, бэкенд, БД, авторизация, формы, бот и т.д.) → проверить глазами пользователя. Отчёт: ссылка на проект, скрин платформы/панели деплоя, скрин работающего проекта, скрин/текст идей от Claude Code, короткое объяснение почему выбрана именно эта платформа.

**Моя рекомендация:** вариант 3 — он один явно рассчитан на реальный, содержательный проект с дальнейшим развитием (в т.ч. скриптами/агентами/MCP, чего и хочет пользователь), варианты 1-2 рассчитаны на учебный лендинг на Beget. Финальный выбор — за пользователем, не решать за него молча.
