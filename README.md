# Zilma

Сайт-визитка поставщика профессиональной косметики для салонов красоты (Wella, Londa, Schwarzkopf, Matrix, Lebel и др.): скачиваемый прайс-лист, интерактивный каталог с оформлением заявки и лента гидов по брендам/оттенкам.

Живой сайт: **https://www.zilma.pro** (он же https://zilma-site.vercel.app). Апекс-домен `zilma.pro` редиректит на `www` — все ссылки/SEO-теги должны указывать на `www.zilma.pro`, не на голый `zilma.pro`.

## Стек

- [Astro 7](https://docs.astro.build) — статические страницы + одна серверная функция (форма заказа)
- Markdown-коллекции контента (`astro:content`) — статьи-гиды
- Деплой — [Vercel](https://vercel.com), автоматически при каждом `git push` в `main`
- Без базы данных: цены и статьи — это файлы в репозитории, заявки уходят в Telegram

## Запуск локально

```sh
npm install
npm run dev
```

Сайт откроется на `http://localhost:4321`.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Локальный сервер с горячей перезагрузкой |
| `npm run build` | Собрать прод-версию в `dist/` (полезно проверить перед пушем — если есть ошибка в контенте, build её покажет, а `dev` иногда молча не запускается) |
| `npm run preview` | Посмотреть собранную прод-версию локально |

## Структура проекта

```
src/

├── layouts/            общий каркас страницы (BaseLayout.astro)
├── pages/               index.astro (главная), articles/[id].astro (шаблон статьи), order.astro (страница «Выбрать и заказать» со своим SEO-превью), api/order.ts (приём заявок)

└── prices/              сами файлы прайса (.xlsx/.pdf), которые скачивают посетители
```

## Как обновить прайс

Сейчас — вручную, редактированием файлов:

1. Заменить файлы в `public/prices/` (`price-current.xlsx` — актуальный прайс, `price-promo.xlsx` — акции).
2. Поправить дату в `src/data/prices.ts` (поле `date` у `currentPrice`/`promoPrice`).
3. Если менялся ассортимент интерактивного каталога (модалка «Выбрать и заказать» на сайте) — обновить `src/data/priceItems.json` (список позиций: бренд, линейка, название, цена, `promo: true/false`).

Больше ничего трогать не нужно — сайт сам подхватит новую дату и файлы.

## Как добавить статью-гид

1. Создать `src/content/articles/ГГГГ-ММ-ДД-название-бренда.md` с фронтматтером по схеме из `src/content.config.ts` (`title`, `description`, `brand`, `line`, `tags`, `coverImage`, `publishDate`, `verifiedDate`, `accent: 'blue' | 'red'`).
2. Картинки — в `public/images/articles/<id-статьи>/`, обложка — просто фото товара на белом фоне (без текста/градиента).
3. **Каждую картинку — через `scripts/optimize-image.py`** (уменьшает до реального размера показа + переводит в WebP, см. раздел «Оптимизация картинок» ниже). Не пропускать этот шаг — иначе PNG в полном размере из PDF/скриншота уедет на сайт как есть, тяжёлый.
4. Для инфографики (пропорции смешивания, время выдержки, чек-листы и т.п.) — использовать готовые CSS-виджеты из `src/pages/articles/[id].astro` (классы `.wheel`, `.mix-card`, `.service-card`, `.checklist`, `.scale-row` и др.), а не картинки-скриншоты из PDF бренда.
5. `verifiedDate` — дата, когда информацию в статье последний раз сверяли с официальным источником бренда (не дата публикации) — она показывается читателю как «Обновлено: …».

## Оптимизация картинок

Все картинки на сайте (`public/images/`) проходят через `scripts/optimize-image.py` — уменьшаются до размера, в котором реально показываются на странице, и сохраняются рядом как `.webp`. Требуется Python + Pillow (`pip install pillow`).

```sh
python scripts/optimize-image.py <категория> <файл1> [файл2 ...]
```

Категории:

| Категория | Где используется | Макс. сторона |
| --- | --- | --- |
| `cover` | обложка статьи (карточка в ленте / шапка статьи) | 1200px |
| `product` | товарное фото в теле статьи | 700px |
| `palette` | палитра оттенков | 1600px |
| `icon` | мелкие иконки/фото шагов (напр. аллерготест) | 400px |

Скрипт не удаляет и не трогает исходный файл — только создаёт `.webp` рядом. Дальше в статье/компоненте нужно сослаться уже на `.webp`-файл, а исходник (PNG/JPG) можно удалить.

## Форма заказа (`/api/order`)

Принимает данные формы и отправляет сообщение в Telegram. Нужны переменные окружения в Vercel (Project → Settings → Environment Variables):

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

Локально для теста формы — создать `.env` с этими же переменными (файл в `.gitignore`, в репозиторий не попадёт).

## SEO

Всё в `src/layouts/BaseLayout.astro`: canonical-ссылка, полный набор Open Graph (`og:title/description/image/url/type` и т.д.), Twitter Card, JSON-LD (`Organization` на главной, `Article` на статьях). Плюс:

- `astro.config.mjs` → `site: 'https://www.zilma.pro'` + интеграция `@astrojs/sitemap` — карта сайта (`sitemap-index.xml`) генерируется автоматически при каждом билде, вручную поддерживать не нужно.
- `public/robots.txt` — ссылается на sitemap, открыт для индексации.
- `public/images/og-default.jpg` (1200×630) — картинка по умолчанию для превью при шаринге ссылки в мессенджерах/соцсетях; у статей вместо неё используется их `coverImage`.
- **Заголовки статей для превью (`og:title`) короче `<title>` вкладки** — полные заголовки статей длиннее 70 символов обрезаются на границе слова через `truncateTitle()` в `src/pages/articles/[id].astro`, чтобы не обрывались на середине слова в Telegram/Twitter.
- **Кеш-бастинг (`?v=N`) у ссылок на favicon/og-картинку** в `BaseLayout.astro` — браузеры и мессенджеры кешируют такие файлы по URL надолго. При реальной смене содержимого favicon/og-картинки — не забыть поднять версию в query, иначе получатели долго будут видеть старый файл.
- Google Search Console / Яндекс.Вебмастер пока **не подключены** — сайт готов к индексации технически (sitemap+robots.txt есть), но статус реальной индексации никто не отслеживает.

## Установка сайта как приложения (PWA)

Сайт можно поставить на телефон как приложение — с иконкой на рабочем столе, без адресной строки браузера при запуске, с офлайн-доступом к уже открытым страницам.

- `public/site.webmanifest` — имя, цвета (`background_color` синий как в Hero, `theme_color` красный как логотип), иконки двух типов: `purpose: any` (круглые, для сплэш-экрана и т.п.) и `purpose: maskable` (квадратные с запасом по краям — под адаптивную систему иконок Android, чтобы она не накладывала свою маску поверх уже круглой картинки).
- `public/sw.js` — простой service worker: network-first с офлайн-кешем для статических GET-запросов, `/api/*` и не-GET запросы явно не трогает (заявки из формы всегда идут живым запросом на сервер).
- iOS-теги (`apple-mobile-web-app-*`) в `BaseLayout.astro` — без них ярлык на iPhone открывался бы как обычная вкладка Safari, а не отдельное приложение.
- `src/components/InstallPrompt.astro` — баннер снизу экрана на каждой странице: на Android/Chrome показывает кнопку «Установить» (реальный системный диалог браузера через `beforeinstallprompt`, появляется только когда браузер сам сочтёт сайт готовым к установке — это нельзя вызвать кодом принудительно), на iOS — статичную инструкцию «Поделиться → На экран Домой» (на iOS программной установки не существует вообще, это единственный способ).
- Исходник иконки (1254×1254, PNG) — `favicon.png` в корне репозитория, не в `public/`. Не удалять — это мастер-файл для пересборки любых размеров иконок.
