# Работа с репозиторием zilma-site

Astro 7 сайт-визитка B2B-поставщика профессиональной косметики для салонов красоты (Wella, Londa, Schwarzkopf, Matrix, Lebel и др.): скачиваемый прайс, интерактивный каталог с оформлением заявки, лента гид-статей по брендам/оттенкам. Живой сайт: https://www.zilma.pro — деплоится автоматически на Vercel при каждом `git push` в `main`.

## Первый шаг в новой сессии

Прочитай `README.md` (технический обзор) и `CLAUDE.md` (полная история решений, дизайн-система, план развития) — не начинай работу вслепую, там уже объяснены нетривиальные решения и грабли, на которые не стоит наступать повторно.

## Запуск локально

```sh
npm install
npm run dev      # http://localhost:4321, hot reload
npm run build    # прод-сборка в dist/ — показывает реальные ошибки контента,
                  # dev-сервер иногда молча не поднимается без объяснения причины
npm run preview  # посмотреть собранную прод-версию локально
```

**Если после правки `.astro`-компонента в браузере не видно новых CSS-правил** — не отлаживать селекторы, сразу перезапустить `npm run dev` (протухший HMR-кэш, известная особенность этого проекта).

## Структура

```
src/
├── components/        UI-блоки (хиро, карточки статей, прайс-блоки, форма заказа, баннер установки PWA)
├── content/articles/  markdown-статьи гидов по брендам (схема — src/content.config.ts)
├── data/               prices.ts (контакты, файлы прайса), priceItems.json (позиции каталога)
├── layouts/            BaseLayout.astro — SEO-теги, PWA-манифест, общий каркас
├── pages/               index.astro, articles/[id].astro, order.astro, api/order.ts
└── styles/global.css   все цвета/шрифты — CSS-переменные --color-*/--font-*, менять только здесь

public/
├── images/              логотип, иконки, товарные фото статей (webp)
├── prices/              файлы прайса (.xlsx), которые скачивают посетители
├── site.webmanifest, sw.js, favicon.*  — PWA-установка
```

## Типовые задачи

**Обновить прайс** — заменить файл(ы) в `public/prices/`, поправить `date` в `src/data/prices.ts`. Если менялся ассортимент интерактивного каталога — обновить `src/data/priceItems.json`. Больше ничего трогать не нужно.

**Добавить статью-гид** — создать `src/content/articles/ГГГГ-ММ-ДД-бренд.md` с фронтматтером по схеме `src/content.config.ts` (`title`, `description`, `brand`, `line`, `tags`, `coverImage`, `publishDate`, `verifiedDate`, `accent`). Картинки — через `scripts/optimize-image.py <категория> <файл>` (сжимает + переводит в webp, категории/размеры — в README). Инфографику оформлять готовыми CSS-виджетами из `src/pages/articles/[id].astro` (`.wheel`, `.mix-card`, `.checklist` и др.), не картинками-скриншотами. **`verifiedDate` поднимать при любой содержательной правке статьи**, не только при добавлении новой.

**SEO/превью при шаринге** — всё в `src/layouts/BaseLayout.astro`. При замене favicon/og-картинки — поднять версию в `?v=N` у соответствующих ссылок, иначе браузеры/мессенджеры долго показывают старый файл из кеша.

## Перед публикацией — обязательно

1. `npm run build` — билд должен пройти чисто, без ошибок.
2. Если правился контент статьи/картинка — `verifiedDate` обновлён.
3. Коммит сразу после проверенной правки, не пачкой в конце сессии (`git add <файлы>` конкретно, не `-A`).

## Деплой

```sh
git add <файлы>
git commit -m "..."
git push origin main
```

Пуш в `main` → Vercel сам собирает и выкладывает, вручную ничего запускать не нужно. Домен — `www.zilma.pro` (канонический; голый `zilma.pro` 308-редиректит на www — ссылки/теги должны указывать на `www`).
